# 覆盖安装数据与主题复查（2026-11-02）

用户反馈从 2.6.0 覆盖安装后“数据都没有了”，但无法确认是配置、密码还是推送记录消失。现有证据不足以确定该用户的数据实际被删除，或确定删除触发点。本轮仅操作本地临时安装目录，未连接或部署 NAS。

## 覆盖安装

已确认的缺陷：`install_callback` 只在配置文件不存在时复制默认配置，但无论是否覆盖安装，都会应用安装向导中的端口、密码，并将密码验证设为开启。覆盖安装因而会修改原访问设置。现在只对首次创建的配置应用向导密码，已有配置和端口保持原值。

已核对仓库中 2.6.0 的原生 FPK 启动脚本：它与当前脚本都使用飞牛提供的 `TRIM_PKGVAR` 作为 `APP_HOME` 和工作目录。普通升级脚本未发现清空整个数据目录的操作；卸载脚本则在明确选择删除数据时执行删除。不能据此断言报告中的全部数据丢失已被解释。

临时环境完整执行安装、覆盖安装和升级回调，验证以下文件逐字节保留：

- `config/config.json`：原渠道、事件选择、密码盐值/哈希和密码开关。
- `config/ui_port`、`config/ui_preferences.json`：原端口及外观。
- `data/cursor/push_stats.json`、历史与待发 SQLite 数据库。
- `data/logs/` 中的既有日志。

首次安装仍创建配置并保存向导设置的加盐密码哈希。回归用真实脚本与临时数据库，仅模拟 pip，避免网络安装依赖。

若仍有用户出现全部内容消失，需要保留其实际应用持久化目录及安装日志，再核对是否发生卸载删除、安装目录变化、权限拒绝或配置读取失败。本轮修复不会凭空恢复已经删除的数据。

## 深色模式

此前所有页面仅从 `localStorage` 读取主题，主页面也直接调用存储 API。浏览器缓存清空、访问 origin 改变或 WebView 禁用存储时，没有服务端恢复来源，存储异常还可能中断页面初始化；未验证反馈用户的宿主具体采用了哪种存储策略。

现在主题通过需鉴权的 JSON 接口保存到 `config/ui_preferences.json`（原子写入、0600），不重写推送配置、不触发监控热加载。页面在渲染时读取服务端偏好并先应用主题；旧浏览器缓存作为无服务端选择时的兼容回退。该偏好属于应用，直连与网关入口保持一致。

配置、记录、帮助和支持页面使用同一份主题脚本。浏览器本地存储不可用时不抛出未处理异常；服务端保存失败时恢复已确认的主题，并在页面提示失败。

真实 Chrome 验证覆盖：禁用 localStorage、关闭并创建全新浏览器上下文、直连/网关、子页面、浅深色切换、保存失败回滚，以及仅打开页面不会写配置。截图保存在 `/private/tmp/fnmb-theme-shots`，属于模拟 API 验证，不是受影响 NAS 的现场截图。

最终验证：完整 pytest 为 **349 passed, 110 subtests passed**；密码开关、权限警告和会话脚本回归通过；basedpyright 修复前后均为 121 项既有错误，无新增；本地 FPK 2.7.5 构建与源码一致性校验通过。改动未发布或部署 NAS。
