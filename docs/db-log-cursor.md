# 主日志游标与迁移

首次运行、游标不存在或损坏时，轮询器从当前日志末尾开始，不补发更早的记录。随后重启会从持久化游标补读停机期间新增的记录。保留 `data/cursor` 挂载才能继续补读。

旧版纯数字游标会在下一次写入时迁移为包含数据库路径、设备号和 inode 的 JSON。数据库文件更换或 ID 回退（例如清空重建）时，从新数据库当前末尾重新对齐，避免把旧记录误当新事件。旧版纯数字游标没有数据库身份资料；若升级时同时更换数据库而新库 ID 仍大于旧游标，无法自动辨识，请在升级前删除旧游标，让首次启动重新对齐。

游标写入使用同目录临时文件与原子替换。持久化失败时保留旧水位并重试；即使已有持久化 outbox 和去重，通知渠道（包括 Telegram）仍不保证 exactly-once 投递。
