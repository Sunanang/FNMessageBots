# 代码审查修复记录（2026-10-24）

开发分支：`dev`，应用版本：`2.7.0`。本轮检查监控事件解析、推送协议与结果统计、配置读写、登录校验和后台资源生命周期。

## 确认并修复的问题

| 问题 | 触发与原行为 | 修复后 |
| --- | --- | --- |
| 平台业务错误误报成功 | 飞书、Bark、PushPlus 返回 HTTP 200，但响应中的业务码代表失败，仍被计为成功 | 分别验证平台的成功码；兼容飞书旧版 `StatusCode`，保留失败原因；PushPlus 使用 HTTPS |
| 通用 Webhook 套用其他平台协议 | 自定义接口返回包含非零 `errcode` 的 JSON，被企业微信规则误判；未完成的 3xx 也可能算成功 | 通用接口只按 HTTP 2xx 判断；内置平台继续按各自协议校验 |
| 同类多个目标隐藏部分失败 | 两个企业微信机器人中只有一个成功时，失败目标和失败计数丢失 | 保存目标明细和成功/失败数量；测试推送出现部分失败时显示错误提示 |
| 慢请求导致磁盘事件丢失 | 定时线程只处理前一个合并窗口，慢请求使更早的窗口被清理 | 取出所有到期窗口逐批处理，网络请求期间释放缓存锁，避免阻塞新事件入队 |
| 去重缓存持续增长 | 每条新日志的源指纹不同，过期项只有关闭时才统一清理 | 后台定期清理，读写与清理使用同一锁 |
| 勿扰汇总状态消息被去重 | 汇总正文和发送状态在同一分钟共用事件类型，后一条被当作重复 | 勿扰系统消息指纹包含正文；相同内容的重复发送仍会拦截 |
| 配置文件形状异常导致页面不可用 | `config.json` 是合法 JSON 数组、标量或 null 时，代码仍调用对象方法 | 返回明确的配置错误，保留文件；环境预置密码不会覆盖异常配置；校验密码字段类型与 UTF-8 编码 |
| 非法 API 参数导致 500 | POST 提交非对象，或保存时提交对象类型的事件、数字类型的渠道地址等 | 在写入前返回 400，保留原配置 |
| 一条异常日志阻塞后续轮询 | 日志 `parameter` 为数组、标量或 null 时，合并用户信息失败，整批无法推进 | 保留原文到 `raw`，继续解析身份与来源并处理后续事件 |
| 热加载失败却提示已生效 | 运行时校验返回 False 后静默退出，配置页提示热加载成功 | 保持原运行配置，并在保存响应中明确提示热加载失败 |
| 密码首字母大小写校验不对称 | 实际密码以小写开头时，首字母大写的不同密码也会被接受 | 保留手机输入法字符兼容，严格区分大小写 |
| 测试推送遗留资源 | 每次测试建立临时通知器，但不停止后台线程和连接池；测试也未传入 Bark 图标 | 成功和异常路径均在 finally 关闭通知器，Bark 测试沿用已配置图标 |

主要回归见 `tests/test_audit_regressions.py`，密码兼容边界见 `tests/test_auth_sessions.py`，部分失败提示见 `tests/check_warning_ui.cjs`。

## 验证

- 修改前：207 项测试、80 个子测试通过。
- 修改后：222 项测试、101 个子测试通过；全部使用临时配置/数据库和模拟推送响应。
- Node 会话竞态检查、登录入口检查，以及密码开关和配置提示的 Playwright 验证通过。
- `2.7.0` FPK 本地构建及校验通过，包含源码、依赖、静态资源与 SHA-256 检查。
- 相同 basedpyright 版本对修改前快照与修改后源码进行对比：错误从 135 项降为 113 项，没有新增错误。原有类型问题仍存在，静态检查未达到零错误。

推送验证确认请求结果和失败识别，未向真实接收人发送消息。PushPlus 同步返回成功仅代表平台接收请求，最终送达状态仍由平台异步处理。
